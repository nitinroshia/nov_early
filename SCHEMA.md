# Canonical financial data schema (generic core + India layer) - v0.1.0

Generated by `build_schema.py` from `src_*.py`. Do not edit this file by hand.

**Files:** `canonical_schema.json` (field registry, entities, conventions, India profile), `vendor_mapping_reli.json` (sample-generator codes to canonical fields), `build_schema.py` (validator and generator), `src_core.py` / `src_fields.py` / `src_mapping.py` (single source of truth).

## Design decisions

1. **Registry first.** Every field is defined once (id, unit, kind, formula, status). Entities are views over the registry. Vendor codes appear only in the mapping file.
2. **Generic core + India layer.** Field names are market-neutral. India specifics live in the market profile, in `scope=india` fields, in enumerations and as `india_term` labels.
3. **Point-in-time facts.** Statement rows are keyed by company, period, reporting basis and revision, and carry `published_date`, so as-of joins cannot look ahead.
4. **Parameterised metrics.** Windows, benchmarks and risk-free rates are parameters, not part of field names (`price_return[window=1y]`, not `52wpct`).
5. **Status per field.** `emitted`, `derivable`, `to_add` show exactly what the generator rebuild must produce.
6. **Catalogue-linked.** Each Part-2 metric points to a canonical field id, which is the bridge to the chart-compatibility matrix.

## India layer (macro level)

| Area | How the schema handles it |
|---|---|
| Fiscal calendar | April-March; `FY2026` ends 2026-03-31; Q1 = Apr-Jun. Dates are plain ISO dates. |
| Currency and scale | INR; statements in crore (`inr_cr`), prices in rupees, shares in crore. Lakh/crore display grouping is a presentation option. |
| Exchanges and ids | NSE primary, BSE secondary; `instrument` carries symbol, series, ISIN, BSE scrip code. `company` carries CIN. |
| Sessions | Effective-dated `trading_calendar`. NSE changed session rules twice in 2026 (closing auction from 2026-08-03, new pre-open from 2026-09-07), so nothing is hard-coded. |
| Reporting | Ind AS vs earlier Indian GAAP, consolidated vs standalone, SEBI deadlines (45 days for Q1-Q3, 60 for Q4/annual), `published_date`, `audit_status`. |
| Ownership | Promoter, FPI, DII (MF, insurance, other), public non-institutional, plus promoter pledging. |
| Market-cap class | AMFI rank-based (1-100 large, 101-250 mid, 251+ small), not a rupee threshold. |
| Benchmarks | NIFTY50 default; SENSEX, Nifty 100/500/Midcap 150/Smallcap 250, India VIX; risk-free IN_TBILL_91D or IN_GSEC_10Y. |
| Market structure | Delivery volume and ratio, price bands, F&O eligibility, lot size, corporate actions (bonus, split, ex/record dates). |
| Templates | `statement_template` = standard_corporate \| bank \| nbfc \| insurance; bank extension planned. |
| Reserved domains | Macro (RBI, MoSPI, FBIL), yield curves, credit ratings (CRISIL, ICRA, CARE...), derivatives, order book, funds (AMFI NAV), portfolio, forecasts. |

Rules in the profile are dated `2026-11-16`; session timings, special-session dates, price bands and derivative rules should be re-verified against exchange circulars before use.

## Conventions

- snake_case ASCII ids; no vendor prefixes; unit is never part of the name (the registry carries it).
- Variant grammar: {metric}[_{aggregation}_{window}] e.g. ebitda_margin_avg_5y, revenue_cagr_5y, revenue_growth_yoy, promoter_holding_chg_1q.
- Parameterised metrics (price_return, volatility, beta...) carry window/benchmark as parameters, not in the name.
- India-specific terms appear as india_term on the generic field, or as scope=india fields.
- **Signs:** expenses positive; cash flow signed by cash effect (outflow negative); drawdown <= 0.
- **Percent:** percent points everywhere (18.4 = 18.4%); spreads use `pp`; multiples use `x`.
- **Nulls:** null means not applicable or unavailable; multiples are null when the denominator is <= 0.
- **Precision:** store full precision, round at presentation.

## Findings in the sample generator

| Severity | Finding | Handling |
|---|---|---|
| high | Payout ratio is a fraction (0.24) while every other ratio is in percent points. | Mapping multiplies by 100; generator should emit percent points. |
| high | balNca excludes balOtha, yet total assets include both. | Mapping sums them into total_non_current_assets. |
| high | balOcl contains short-term debt as well as other current liabilities. | Synthetic mapping splits it using balTdeb - balTltd. |
| medium | Capex and dividends paid are positive while investing/financing totals are signed. | Mapping negates them (cash-effect sign convention). |
| medium | Code 'earnings' is the 5-year CAGR of EBITDA, not earnings. | Mapped to ebitda_cagr_5y. |
| medium | incOpe is the residual 'other operating expense'; qIncOpeK is total opex. | Different canonical fields. |
| medium | ROIC divides by gross capital; EV/IC uses capital net of cash. | Both kept; definitions documented. Pick one. |
| medium | Date-only values are emitted as midnight UTC timestamps. | Mapping converts to plain dates. |
| medium | Peer snapshots are not derived from peer histories: epsg is net-income growth, risk uses monthly returns, and qcur/aint/ccnc are random. | Replace with the shared company engine (next step). |
| medium | Fixed Rs 20,000 cr threshold; Indian practice is the AMFI rank-based list. | Mapped to rank-based enum; generator should rank within a universe. |
| low | Recommendation figures are constants for the subject and random for peers. | Model consensus properly when the estimates domain is built. |
| low | Several codes duplicate others under a different name. | Mapped to the same canonical field; drop duplicates at the source. |
| low | Market cap uses fiscal-year share count; EV omits minority interest and investments. | Documented in field notes. |
| low | TTM row takes dividend from the latest fiscal year, not trailing quarters. | Flag when rebuilding TTM. |
| low | Output is rounded to 2 decimals, which loses precision for small ratios and betas. | Store full precision; round at presentation. |
| low | Trading calendar uses a handful of fixed-date holidays, no Muhurat/special sessions. | Use the trading_calendar entity with the real exchange list. |
